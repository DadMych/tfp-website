# Data processing summary

This is the data-processing summary for Northwind Studio, Lloydkwartier, Rotterdam. It is dated 1 January 2026. It describes how the studio handles personal data that sits inside client files. The master services agreement remains the contract; this summary is the part of it that deals with that data.

## 1. Roles

1.1 Where personal data is contained in files the client supplies, or in files Northwind produces for the client, the client decides the purposes of that data and Northwind acts as processor.

1.2 "Files" in this summary means design files, briefs, feedback, exports, and other project material held for the engagement. It includes material stored in Figma and in Harbor, the client portal.

1.3 Northwind processes that data only so it can do the work the client has asked for: design, review, handoff, and storage of the files for the retention period below.

1.4 This summary does not turn Northwind into the processor for the client's own product, users, or databases. Northwind does not run the client's software.

## 2. What is processed, and for how long

2.1 The data is whatever personal data happens to be inside those files.

2.2 Processing runs for the engagement and then for the retention period in clause 5.

2.3 Project files are kept for 24 months after the last invoice. Invoices are kept for 7 years.

## 3. Hosting

3.1 Data is hosted in the EU.

3.2 Harbor, the client portal for requests, files, and invoices, is part of that EU hosting. Harbor launched in May 2025 and replaced email-only requests.

## 4. Sub-processors

4.1 Northwind uses the following sub-processors for client data in files:

4.1.1 Figma, for design files.

4.1.2 Google Workspace, for email and documents exchanged with the client.

4.1.3 Harbor's hosting, for the client portal.

4.2 Northwind stays responsible to the client for processing done by those sub-processors under this summary. The sub-processors for client project data are the three named in clause 4.1.

4.3 Development partners (separate studios the client may hire for code) are not sub-processors of Northwind. The client contracts them directly. They are not covered by this summary.

## 5. Retention, deletion, and access

5.1 Project files are deleted after 24 months from the last invoice, unless the client has asked for deletion sooner.

5.2 A deletion request must be in writing. Northwind confirms the deletion within 10 working days.

5.3 Invoices are kept for 7 years and are not destroyed as part of a file-deletion request.

5.4 Figma access for the client's people is removed 30 days after the end of the engagement. The client should export files before then, or ask for an export through Harbor.

## 6. Breaches

6.1 If Northwind becomes aware of a personal data breach affecting client data it holds as processor, Northwind notifies the client within 48 hours.

6.2 The notice says, as far as is known then, what happened, which files or data are affected, and what has been done to contain it. If those facts are incomplete at 48 hours, Northwind sends what it has and follows with the rest.

6.3 The notice in clause 6.1 goes to the client. The client, as the party which decides the purposes of the data, remains responsible for any notice the client owes to a person or an authority. This summary does not set a second clock for that notice.

## 7. Instructions and return

7.1 Northwind follows the client's documented instructions for this data. Those instructions are the agreement, the statement of work, and requests made through Harbor or by email to the account lead.

7.2 If an instruction would require Northwind to process the data in a way this summary does not allow, Northwind tells the client before doing it.

7.3 At the end of the engagement, or on a written request during the retention period, Northwind provides an export of the project files through Harbor. Clause 5 still applies after the export.

7.4 Questions about this summary go to the account lead, who involves operations.
