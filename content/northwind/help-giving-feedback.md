# How to give feedback that works

Each deliverable includes two rounds of revisions. A round is one response from you, not a week of separate nudges. The quality of that response decides whether the next version is sharper or just different.

## One list, one approver

Collect comments on your side first. Then send a single list for the round. Put it in one place: Figma comments, or one Harbor message. Not both, and not a trail of afterthoughts in other channels. If a note is not in that list, it is not in the round.

Name one approver in the list. Other colleagues can help you draft it. One person decides, so we are not left with two yeses and a no on the same screen. If you cannot name one approver, the round is not ready to send.

## Timing

Send feedback within 5 working days. We plan the next version around that.

If a round sits in silence for 10 working days, it is accepted. We move on. A late note after that is a new round, not a continuation of the quiet one. If you need the days, say so before they run out. Silence is not a way of holding the work open.

## What a useful round looks like

This is a round we can act on:

> Round 2. One approver: our head of product.
> 1. The hero still uses the old product name. Use the name from the brief.
> 2. The empty state for the list is missing. Show it when there are no items yet.
> Nothing else this round.

This is not:

> Monday: a Figma comment that says "make it pop". Wednesday: an email asking for the headline to be shorter, from someone else. The week after: a chat message adding a new section. No one named as one approver. Three directions, none of them finished.

"Make it pop" does not tell us what is wrong. A second channel the next day does not add to the round; it starts a mess. A new page, slipped in at the bottom, is a new request, not a revision of the page we sent.

Point at the frame, say what should change, and stop when the list is complete. We would rather have four precise lines than twenty impressions.
